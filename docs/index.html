How it works

No magic, no guessing. Just the same compiler the game was built with.

Every game starts as code written by people. A program called a compiler turns that code into the machine code your PC or Xbox runs. Scarface's original code was never released.

So we write it again. Each small piece of the game, called a function, is rewritten in C++ and run through the same compiler the developers used: Microsoft Visual C++ 7.1, from 2003. When the result is identical to the game, byte for byte, that function is done. Nobody has to take anyone's word for it: the compiler decides.

The PS2 version was built from the same code with a different compiler, Metrowerks CodeWarrior for PS2. That one runs on decomp.me, so PS2 functions are compiled there and checked the same way, against your own copy of the game.

  • Same bytesSame length and same machine code as the original game.
  • Same connectionsEvery jump, call and variable points where the original did.
  • No shortcutsCode refers to other functions and data by name, never by a raw memory address.
  • Real C++No hidden assembly or tricks that just copy the bytes.

The full rules: METHODOLOGY.md

    Start helping

    You don't need to be an expert. If you can read a little C++, or want to learn, small functions take minutes. Everything runs on your computer and your game files are never uploaded.

    • Python 3 and Git (both free)
    • Your copy of the Xbox game
    • About 10 minutes to set up
    • Strongly recommended: Visual C++ Toolkit 2003 (VCToolkitSetup.exe)

    Four steps, and one file does the setting up. Have the compiler's installer if you can: the portal then checks your work on the spot and credits you right away; without it, a maintainer checks it for you (step 2). The game and the compiler are the only two things the project can't give you: they belong to their owners, so they are never on GitHub.

    1. Run the setup fileOn Windows, download scarface-setup.bat and double-click it. It installs Python and Git if you don't have them, puts the project in a scarface_decomp folder on your Desktop, opens it for the next step, and then starts the portal. Run it again any time to update. Windows may ask whether to run a downloaded file: choose More info, then Run anyway; it is plain text, so you can read it first. On Mac or Linux, or to do it by hand: install Python 3 from python.org and Git from git-scm.com, then run git clone https://github.com/scarface-decomp/scarface_decomp.git in a terminal, and git pull in that folder to update later. Rather not use Git? On GitHub press Code, then Download ZIP; see CONTRIBUTING.md for how to update one.
    2. Drop in your two filesPut your game in the project's binaries folder, just as you have it: the US Xbox disc image (.iso, .zip or .7z) is the one that matters, and the PC game with its 1.00.2 patch is an optional extra. Put the compiler's installer, VCToolkitSetup.exe (Microsoft's Visual C++ Toolkit 2003, which the game was built with), in the project folder itself (or leave it in your Downloads folder). Nothing has to be installed, unpacked or typed. Where to find them: the game is yours to bring, from your own disc. Microsoft gave the Toolkit away for free and no longer offers it; the Internet Archive keeps a copy of VCToolkitSetup.exe. The PC game's official 1.00.2 US patch is no longer on its publisher's site either; there is a copy on Nexus Mods (a free account is needed). The portal checks both and refuses a file that isn't the real one. No compiler? The portal still runs. Use its decomp.me button, which compiles in your browser, get the function to 100% there and post the link in a GitHub issue or in #help on Discord; your scratch is filed under the Scarface preset and a maintainer verifies it and credits you.
    3. Start the portalBack in the setup window, press a key and it starts. From then on, double-click START_PORTAL.bat in the project folder. On Mac or Linux, run sh start_portal.sh. The first start takes a few minutes: it installs what it needs, sets up the compiler, checks and unpacks your game and lists every function. Then your browser opens the portal at localhost:8085. Only the US versions of the game are accepted; it tells you if something is off.
    4. Match functions, then submitSign in (the first time, just pick a name and a PIN), choose a small function and claim it. The editor starts you off with a first draft of its C++, written from the game's machine code; for many small functions the draft already matches. Press Compile & Verify, and change the code until it says 100%: it is recorded under your name. When you're done for now, press Submit your work in the sidebar. It puts your new matches in one file: post it in the Discord or a GitHub issue, and a maintainer adds them under your name after compiling each one again. Your matches are saved on your computer as you go, so nothing is lost if you close the portal first.

      Questions

      The things people usually ask first.

      What is a function?

      A small, named piece of the game's code that does one job, like checking whether a door is open or adding money to your empire. The game has about 21,000 of them. Many are only a few lines long.

      Do I need to know C++?

      A little helps, but you can learn as you go. The smallest functions are a line or two, the portal writes a starting guess for you, and Compile & Verify shows exactly which bytes still differ.

      Do I need the game?

      Yes. The project shares only the code people write, never the game. The portal reads your own copy (default.xbe from the Xbox disc, and Scarface.exe 1.00.2 if you have the PC game) on your computer.

      Which version of the game do I need?

      The US Xbox disc, exactly: that's where almost all of the work is. The US PC game with the official 1.00.2 patch installed, the US PS2 disc and the April 2006 Xbox prototype are optional extras. Every function is matched against those exact files, and other versions have different code at different addresses, so the portal won't use the unpatched PC 1.00, other regions' discs or edited files. The accepted files and how to check yours are in GAME_VERSIONS.md.

      I play on PC. Why is the Xbox version the main one?

      Because both versions are the same game, built from the same C++ with the same compiler, and only the Xbox one can be read in full. Every byte of game code in default.xbe is plain machine code. In the PC's Scarface.exe 1.00.2, only about a tenth is (84 of its 814 code pages); the rest is encrypted in the file. That leaves about 1,500 PC functions to work on, against about 19,500 on Xbox. Almost all of the game's code is shared, so rebuilding the Xbox version rebuilds most of the game; the next answer covers the parts each version has to itself.

      Doesn't the Xbox version run differently from the PC version?

      Only where the hardware differs. Of the game's C++ classes, 2,421 are in both versions. The Xbox has 34 of its own, mostly for its controller, saving, sound and graphics; the PC has 36 of its own, mostly keyboard and controller setup menus, DirectInput, Windows files, Ogg Vorbis sound, HDR and display settings. And when the same function exists in both, its machine code is usually identical apart from addresses, but not always: of the PC class methods that can be read, 456 have exactly the same code as on Xbox and 176 differ. So the Xbox work rebuilds the shared game, and the PC-only parts still have to come from the PC version. About 90 of the PC-only class methods can be read; the rest of the PC-only code is in the encrypted part.

      Does it cost anything?

      No. Python, the portal and decomp.me are free. The 2003 compiler was a free download from Microsoft; it isn't offered any more, so you need your own copy of its installer, VCToolkitSetup.exe.

      Is this allowed?

      The repository contains only code written by contributors, under the GPL. It contains no game files, assets or compiler, and it isn't affiliated with the game's owners. The details are in LEGAL.md (not legal advice).

      What about the PlayStation 2 and Wii versions?

      The PS2's scripts are done: its compiled scripts are the same files as the Xbox's, and every one of them decompiles to readable TorqueScript that compiles back to the identical file. Load your PS2 disc image into the portal and its Game Scripts tab shows them.

      The PS2's C++ code is a different matter. Its program runs on the PS2's MIPS processor and was built with Metrowerks CodeWarrior for PlayStation 2, not Microsoft's compiler, so matching it needs that compiler and its own setup, which nobody has started yet. It's the version most worth doing: it has things the PC version lacks, such as its blood effects on clothing and skin and its own explosion sounds. The Wii version mostly changed the controls and some tuning, so there's less in it that the others don't have, but it's open too. What we know so far, and what a PS2 setup would need, is in OTHER_VERSIONS.md.

      What about the Xbox prototype?

      It's part of the goal: the game that shipped, plus the code that never shipped. The April 20, 2006 prototype (game.xbe) is in the portal, all of its code can be read, and every match is saved in the repository like any other (reconstructed_src/proto/). About half of its 17,900 functions have the same machine code as a retail Xbox function, so they get matched along with retail ones. The rest changed before release, or belong to classes the retail game doesn't have, such as PlaneCamera, MortarWeaponTemplate, DebugCamera and network debugging tools. Its progress has its own row, so the main percentage keeps measuring the released game and isn't inflated by the copies it shares with it.

      Why do some functions get done in batches?

      Many functions are copies of each other with different addresses: the same template made for different classes, or the same function in the PC and Xbox versions. In the retail game, about 4,600 functions have such a look-alike. When you match one, the portal swaps the addresses and names into your code, tries it on each look-alike with the real compiler, and credits you for every exact match. The portal lists these functions first.

      What about the game's scripts?

      The game also runs compiled scripts (.cso and .dso files), written in TorqueScript, a C++-like language. All 635 of the released game's compiled scripts (the same files on PS2, Xbox and PC) and all 864 of the April 2006 prototype's now decompile to readable TorqueScript that compiles back to the identical file, checked by a compiler that lays the bytes out exactly as the game's did. The game stores names as hashes; about half are recovered as real words so far. The AI's decision tree (.dtr) is decoded too, apart from the small programs inside it. Details in SCRIPTS.md.

      Can I get the game's textures, sounds and movies?

      Yes, from your own copy of the game, with the portal's Game files tab. The list sorts every file by type (sounds, textures, models, animations, videos, scripts and text): sounds play with their subtitles, movies play in the page (made playable once with FFmpeg), and Export every texture writes all the game's textures out as .png: the PC's, plus what only the Xbox, PS2 and 2006 prototype have. Where the prototype has the same picture at twice the resolution (some world textures), that one is used; its bigger menu icons are different pictures, so they're kept apart. The textures live inside the game's .p3d files; how the versions compare is in FORMATS.md. Copying uses every processor core when your discs are on a fast drive; a graphics card helps only with movies. Nothing is uploaded or shared.

      Can I open the game's models and map in Blender?

      Yes, from your own copy of the game. In the portal's Game files tab, press Copy everything, PC first (the PC's files are the best for this, and the other versions add what the PC doesn't have), then press Open next to any model, or pick a map area or the whole city in the In Blender box, and press Open in Blender: your Blender starts with the scene in it and saves it as a .blend. A downloaded .glb goes in with File > Import > glTF 2.0 (double-clicking one makes Blender say it isn't a valid Blender file). You get characters with their skeletons, skin weights and animations, the game's cameras with their moves, guns, cars with their moving parts, and each part of the city with the trees, lamps, benches and signs the game places on it, at their places; the whole city opens as one scene. The Xbox, PC and PS2 files all work. Traffic and pedestrians aren't in the files: the game spawns them as it runs. How the models, animations and map are stored, and how to do it from the command line, is in FORMATS.md. Nothing from the game is ever uploaded or shared: the scenes are made on your computer.

      I'm stuck. Where do I ask?

      Ask in #help on the Discord (joining takes a short application, to keep bots out), or open an issue on GitHub. Include the function's address and what you tried. Near misses are useful too. If the portal won't start or can't check your code, run python portal/doctor.py in the project folder first: it checks your setup and says how to fix each problem, and --share gives a copy that's safe to paste.
