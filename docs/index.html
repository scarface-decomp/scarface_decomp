How it works

No magic, no guessing. Just the same compiler the game was built with.

Every game starts as code written by people. A program called a compiler turns that code into the machine code your PC or Xbox runs. Scarface's original code was never released.

So we write it again. Each small piece of the game, called a function, is rewritten in C++ and run through the same compiler the developers used: Microsoft Visual C++ 7.1, from 2003. When the result is identical to the game, byte for byte, that function is done. Nobody has to take anyone's word for it: the compiler decides.

  • Same bytesSame length and same machine code as the original game.
  • Same connectionsEvery jump, call and variable points where the original did.
  • No shortcutsMemory addresses from 2006 can't be typed in as numbers.
  • Real C++No hidden assembly or tricks that just copy the bytes.

The full rules: METHODOLOGY.md

    Start helping

    You don't need to be an expert. If you can read a little C++, or want to learn, small functions take minutes. Everything runs on your computer and your game files are never uploaded.

    • Python 3 (free)
    • Your copy of the game
    • About 10 minutes to set up
    1. Install PythonGet Python 3 from python.org. On Windows, tick Add python.exe to PATH on the installer's first screen.
    2. Download the projectOn GitHub, press Code, then Download ZIP, and unzip it anywhere. If you use Git: 
      git clone https://github.com/scarface-decomp/scarface_decomp.git
    3. Add your game filesCopy Scarface.exe (US PC version 1.00.2) and/or default.xbe (from the US Xbox disc) into the project's binaries folder. Only these US versions are accepted; the portal checks. Use the files themselves, not the download they came in: default.xbe is inside the Xbox disc image, and Scarface.exe is in the folder the PC game is installed to. The portal can't open a .iso, .7z or .zip. Optional: game.xbe from the April 2006 Xbox prototype adds its unreleased code.
    4. Start the portalOn Windows, double-click START_PORTAL.bat. On Mac or Linux, run sh start_portal.sh. Your browser opens the portal at localhost:8085.
    5. Pick a function and solve itChoose a small one. The editor starts you off with C++ written from the game's own code, and for many small functions that already matches. Change it until it does.
    6. Verify itPress Compile & Verify to record it under your name. That needs the 2003 compiler, installed once from your own VCToolkitSetup.exe: 
      python portal/scripts/setup_msvc71.py VCToolkitSetup.exe
      No compiler yet, or it's acting up? Press decomp.me in the portal instead: it runs the same compiler in your browser. Get it to 100% there and post the link in a GitHub issue, and a maintainer will verify it and credit you.

    Questions

    The things people usually ask first.

    What is a function?

    A small, named piece of the game's code that does one job, like checking whether a door is open or adding money to your empire. The game has about 21,000 of them. Many are only a few lines long.

    Do I need to know C++?

    A little helps, but you can learn as you go. The smallest functions are a line or two, the portal writes a starting guess for you, and Compile & Verify shows exactly which bytes still differ.

    Do I need the game?

    Yes. The project shares only the code people write, never the game. The portal reads your own copy (Scarface.exe 1.00.2 for PC or default.xbe from the Xbox disc) on your computer.

    Which version of the game do I need?

    The US versions, exactly: the US Xbox disc, and/or the US PC game with the official 1.00.2 patch installed. Every function is matched against those exact files, and other versions have different code at different addresses, so the portal won't use the unpatched PC 1.00, other regions' discs or edited files. The April 2006 Xbox prototype is an optional extra. The accepted files and how to check yours are in GAME_VERSIONS.md.

    Does it cost anything?

    No. Python, the portal and decomp.me are free. The 2003 compiler was a free download from Microsoft.

    Is this allowed?

    The repository contains only code written by contributors, under the GPL. It contains no game files, assets or compiler, and it isn't affiliated with the game's owners. The details are in LEGAL.md (not legal advice).

    Can all of the game's code be read?

    On Xbox, yes: every byte of the game code in default.xbe is plain machine code. On PC (Scarface.exe 1.00.2), only about a tenth is (84 of its 814 code pages); the rest is encrypted in the file, so the portal only hands out PC functions from the readable part. The Xbox version runs the same game code; only the parts for each machine's hardware differ (see the next question).

    Doesn't the Xbox version run differently from the PC version?

    Only where the hardware differs. Of the game's C++ classes, 2,421 are in both versions. The Xbox has 34 of its own, mostly for its controller, saving, sound and graphics; the PC has 36 of its own, mostly keyboard and controller setup menus, DirectInput, Windows files, Ogg Vorbis sound, HDR and display settings. And when the same function exists in both, its machine code is usually identical apart from addresses, but not always: of the PC class methods that can be read, 456 have exactly the same code as on Xbox and 176 differ. So the Xbox work rebuilds the shared game, and the PC-only parts still have to come from the PC version. About 90 of the PC-only class methods can be read; the rest of the PC-only code is in the encrypted part.

    What about the PlayStation 2 and Wii versions?

    They aren't in the portal yet, and anyone who wants to start on them is welcome to. The PS2 version is the one most worth doing: it has things the PC version lacks, such as its blood effects on clothing and skin and its own explosion sounds. Its program runs on the PS2's MIPS processor and was built with Metrowerks CodeWarrior for PlayStation 2, not Microsoft's compiler, so it needs its own matching setup with that compiler. The Wii version mostly changed the controls and some tuning, so there's less in it that the others don't have, but it's open too. What we know so far, and what a PS2 setup would need, is in OTHER_VERSIONS.md. The PS2 disc's compiled scripts are already used for the script work.

    What about the Xbox prototype?

    It's part of the goal: the game that shipped, plus the code that never shipped. The April 20, 2006 prototype (game.xbe) is in the portal, all of its code can be read, and every match is saved in the repository like any other (reconstructed_src/proto/). About half of its 17,900 functions have the same machine code as a retail Xbox function, so they get matched along with retail ones. The rest changed before release, or belong to classes the retail game doesn't have, such as PlaneCamera, MortarWeaponTemplate, DebugCamera and network debugging tools. Its progress has its own row, so the main percentage keeps measuring the released game and isn't inflated by the copies it shares with it.

    Why do some functions get done in batches?

    Many functions are copies of each other with different addresses: the same template made for different classes, or the same function in the PC and Xbox versions. In the retail game, about 4,600 functions have such a look-alike. When you match one, the portal swaps the addresses and names into your code, tries it on each look-alike with the real compiler, and credits you for every exact match. The portal lists these functions first.

    What about the game's scripts?

    The game also runs compiled scripts (.cso, .dso and .dtr files), written in TorqueScript, a C++-like language. They get the same treatment: a readable version that only counts once it turns back into exactly the original bytes. So far all 635 compiled scripts are read and rebuilt byte for byte; turning them into readable TorqueScript is next. The plan is in SCRIPTS.md.

    I'm stuck. Where do I ask?

    Open an issue on GitHub with the function's address and what you tried. Near misses are useful too.
