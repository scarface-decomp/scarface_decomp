# Project website

`docs/index.html` is the public project page, live at **https://scarface-decomp.pages.dev**: progress,
the verified functions with their code, and how to help. It has no build step and no dependencies, and apart from its data fallback (below) it loads nothing from other sites.
It is hosted on the project's Cloudflare account (`scarface-decomp` Pages project), which rebuilds it
on every push to `main`.

## What's in this folder

| File | What it is |
| :--- | :--- |
| `index.html` | The page itself: markup and styles. The skyline is inline SVG, drawn for this site. |
| `js/` | Each page's script (`site.js` for `index.html`, `function.js`, `versions.js`). Pages have no inline script or `onclick=`, because the security policy in `_headers` refuses them. |
| `fonts/` | The fonts (Anton, Josefin Sans, Marcellus; SIL Open Font License, licences beside them) and `fonts.css`. The portal serves the same files. |
| `_headers` | The response headers Cloudflare Pages adds to every file: a Content-Security-Policy (only the site's own scripts, fonts and pictures; data only from the site and raw.githubusercontent.com), no framing by other sites, and a few more. Add any new outside address the pages need here, or browsers refuse it. |
| `404.html` | Shown by Cloudflare Pages for any address that doesn't exist. |
| `favicon.svg`, `favicon-32.png`, `apple-touch-icon.png` | Browser and phone home-screen icons. |
| `og.jpg` | The 1200 x 630 preview shown when the link is shared on Discord, Reddit, X and so on. |
| `function.html` | One rebuilt function's own page (`function.html?f=xb:0x001CDC80`): what it does, who rebuilt it, a link to its C++ on GitHub (its exact lines), what it uses and what uses it. Read from `functions.json`, like the main page's list. |
| `functions.json` | Every rebuilt function, for the list and the function pages: names, sizes, who, what it does, and the file and lines of its C++ on GitHub. No code, so the site stays quick however many functions are rebuilt. Generated by `portal/tools/registry_outputs.py` from the registry (the portal's Sync commits it); don't edit it by hand. |
| `versions.html`, `versions.json` | What differs between the versions: the page, and its data (made by `portal/tools/version_report.py`, names only). |
| `feed.xml` | An Atom feed of the newest matches (generated by `portal/tools/registry_outputs.py`), for feed readers and Discord feed bots. |
| `robots.txt`, `sitemap.xml` | For search engines. |
| `*.md` | Project documents linked from the page and the README. |

## Where its data comes from

The scoreboard reads `reports/progress.json`, which the portal and `portal/scripts/reverify_all.py` keep up to
date. It looks for it in this order:

1. `data/` next to the page. The Cloudflare Pages build copies it there on every push.
2. The repository on `raw.githubusercontent.com`. That covers GitHub Pages, or a deploy without
   step 1.

The list of rebuilt functions is `functions.json`, beside the page (or the repository's `docs/` folder on
`raw.githubusercontent.com`). The code itself is only on GitHub: the site links each function to its lines in
`reconstructed_src/<version>/<subsystem>/<Class>.cpp`.

So every push to `main`, including the portal's **Sync to GitHub**, updates the site.

## Cloudflare Pages settings

| Setting | Value |
| :--- | :--- |
| Production branch | `main` |
| Framework preset | None |
| Build command | `mkdir -p docs/data && cp reports/progress.json docs/data/` |
| Build output directory | `docs` |

## Testing locally

```bash
python -m pytest -q portal/tests/test_site_e2e.py
```

Or serve it yourself: copy `reports/progress.json` into `docs/data/` (ignored by git) and run
`python -m http.server -d docs 8000`, then open http://localhost:8000.
