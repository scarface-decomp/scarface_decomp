How the 1:1 C++ Decompilation Pipeline Works

                
Inspired by community matching-decompilation projects such as fnvdecomp.com.

              

            


            

              

                
Phase 01 • Ground Truth

                
Readable x86 First

                
All of the retail Xbox game code (default.xbe) can be read. Only about a tenth of PC v1.00.2's (Scarface.exe, 84 of 814 code pages) can; the rest is encrypted, so the queue only hands out PC functions from the readable part. The two builds share 2,421 C++ class names. Each function's exact bytes are disassembled from your own copy of the game, and functions with the same machine code are grouped as look-alikes, so one match can cover many.

              

              

                
Phase 02 • Translation

                
Genuine Human-Readable C++

                
Contributors (assisted by the local C++ pattern recognizer and AI APIs) rewrite each function as genuine C++ classes, structs, and methods. Inline assembly (__asm, _emit, naked) and raw byte tricks are rejected by the verifier.

              

              

                
Phase 03 • Byte-Exact Proof

                
Original-Era Compiler (MSVC 7.10)

                
Every submission is compiled with the Visual C++ Toolkit 2003 (cl.exe 13.10.3052, MSVC 7.1) using the task's flags (usually /O2 /Ot /Oy /G6 /Gd /GR /EHsc /Zp4). The compiled function must have exactly the original's length and bytes; relocations must point where the original's do, and hard-coded 2006 addresses don't count.

              

              

                
Phase 04 • Dual GitHub Sync

                
Binary Order + Subsystem Tree

                
Verified functions are recorded in reports/verified_registry.json; from it the server regenerates Original_Binary_Order_PC_1002.cpp / Original_Binary_Order_Xbox.cpp (address order) and pc/, xbox/ subsystem folders. Maintainers push them to GitHub.

              

            


            

              
Legal & Preservation Policy

              
This portal and the project repository distribute no game executables, archives, scripts, or other game assets, and no leaked studio source code is present or permitted. To use the tools you need your own legally obtained copy of the game.

              
All C++ in the repository is written by contributors and checked against the original binary for modding interoperability, bug-fix research, and software preservation. This project is not affiliated with or endorsed by the game's developer or publishers.
