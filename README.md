**Website and live progress: [scarface-decomp.pages.dev](https://scarface-decomp.pages.dev)**

A matching decompilation of **Scarface: The World Is Yours** (Radical Entertainment, 2006): C++ source
that compiles, with the compiler the game was built with, to the same machine code as the game. It is
meant for modding research, engine bug fixing and preservation.

> This repository contains reconstructed source code and tools only. It contains no game executables,
> no game assets and no compiler. You need your own copies of the game files and of the Visual C++
> Toolkit 2003 installer to verify anything.

Every number here is produced by the compiler, not typed by hand: `scripts/reverify_all.py` recompiles
every claimed function with the real compiler, and the portal adds each new match the moment it
verifies. The work queue holds every function that can be read: all of the Xbox version's game code
and the readable tenth of PC 1.00.2 (the rest of the PC file is encrypted), about 21,000 functions;
`python verify.py --status` prints the exact numbers, and `reports/reverify_report.md` lists every
claimed function and why it does or does not count.

## Help wanted

This is a community project and every bit of help counts, from your first 5-byte function to
naming classes and documenting the engine. You don't need to be an expert: the portal hands you one
function at a time, shows the original bytes and disassembly, and tells you exactly how close your
C++ is. See [CONTRIBUTING.md](CONTRIBUTING.md) to get started.

**PS2 or Wii?** Those versions aren't in the portal yet, and anyone who wants to start a PS2 (or Wii)
decomp is welcome to. The PS2 version has things the PC lacks, such as its own blood effects and
explosion sounds. What we know so far and what it would take: [docs/OTHER_VERSIONS.md](docs/OTHER_VERSIONS.md).

## What "verified" means

A function counts only when the compiled C++:

1. has **exactly the length and bytes** of the original, apart from the 4-byte fields the linker fills in;
2. passes the **relocation checks**: internal jumps land at the same offsets, data it defines matches what
   the original points at, and symbols named for an address (`DAT_00439DA4`) are that address;
3. contains **no 2006 address written as a number**;
4. is **plain C++**: no inline assembly, `_emit`, `naked` functions or section tricks.

The full procedure, with code generation notes for this compiler, is in
[docs/METHODOLOGY.md](docs/METHODOLOGY.md).

## Quick start (no experience needed)

1. **Install Python 3** from [python.org](https://www.python.org/downloads/). On Windows, tick
   *Add python.exe to PATH* on the installer's first screen.
2. **Download this project**: on GitHub press **Code**, then **Download ZIP**, and unzip it anywhere
   (or `git clone` it).
3. **Add your game files** to the `binaries` folder: `Scarface.exe` (PC, US version 1.00.2) and/or
   `default.xbe` (Xbox, US disc). Only these exact US versions are accepted, and the portal checks:
   see [docs/GAME_VERSIONS.md](docs/GAME_VERSIONS.md). They never leave your computer. `game.xbe` (the April 20, 2006 Xbox prototype) is
   optional: with it, the prototype's functions are added too. The goal is the released game plus the
   code that never shipped; prototype matches are saved in `reconstructed_src/proto/` and counted on
   their own row.
4. **Start the portal**: on Windows double-click **`START_PORTAL.bat`**; on macOS or Linux run
   `sh start_portal.sh`. It installs what it needs the first time and opens http://localhost:8085.
5. **Pick a small function** and press **decomp.me**. It opens on [decomp.me](https://decomp.me), which
   runs the same compiler in your browser. Change the C++ until it shows 100%, then paste it back into
   the portal.
6. **Press Compile & Verify** to record it under your name. That needs the compiler (below). No
   compiler? Post your 100% decomp.me link in a [GitHub issue](../../issues/new) and a maintainer will
   verify it and credit you.

Only the function you send leaves your computer: decomp.me receives that one function's bytes, the
same as any decomp.me scratch. decomp.me's score is a helper; the portal's check is what counts.

## The compiler

From your own `VCToolkitSetup.exe` (Visual C++ Toolkit 2003):

```bash
python scripts/setup_msvc71.py path/to/VCToolkitSetup.exe
```

This installs `cl.exe` 13.10.3052 with its headers and libraries into `tools/msvc71/`. On Windows it
runs natively. On Linux and macOS it runs under Wine with a 32-bit prefix, for example
`export WINEPREFIX=$HOME/.wine32 WINEARCH=win32 WINEDEBUG=-all` (extraction needs `msitools`).
Set `SCARFACE_MSVC_BIN` to use a compiler somewhere else. The Toolkit is not redistributable, so
`tools/msvc71/` is never committed. The SHA-256 of the game files the registry was verified against is
in `reports/verified_registry.json` under `binaries`.

## Working on functions

**In the portal** (http://localhost:8085): sign in with a handle and a PIN of at least 8 characters,
claim a function from the queue, write the C++ (in the editor, on decomp.me, or with your own AI key),
and press **Compile & Verify**. A match is recorded in `reports/verified_registry.json`, and the
generated source files are rewritten. About 4,600 functions are look-alikes of another (the same
machine code with different addresses); after a match the portal swaps the addresses and names into
your code, verifies it on each look-alike and credits you for every exact match
([tools/lookalikes.py](tools/lookalikes.py)). The queue lists one function of each group first. Manual start: `pip install -r requirements.txt`, then
`python decomp_portal_server.py`.

| Variable | Default | What it does |
| :--- | :--- | :--- |
| `SCARFACE_HOST` | `127.0.0.1` | interface to listen on; the portal is local-only by default |
| `SCARFACE_PORT` | `8085` | port the portal listens on |
| `SCARFACE_MAINTAINERS` | `RRutherrfordd (Founder)` | handles allowed to use "Sync Verified to GitHub" |
| `SCARFACE_NO_BROWSER` | unset | `1` stops it opening a browser |
| `SCARFACE_DECOMPME_URL` | `https://decomp.me` | where the decomp.me button sends functions |
| `SCARFACE_LOOKALIKE_MAX` | `1000` | how many look-alikes a new match is tried on |
| `SCARFACE_MSVC_BIN` | `tools/msvc71/bin` | where `cl.exe` 13.10.3052 is, if not there |

**From the command line**, with the same rules:

```bash
python verify.py my_func.cpp --va 0x006DE620 --bin pc
python verify.py my_func.cpp --va 0x00011F20 --bin xb --match vfunc_03@Collidable@ --show-diff
```

**Maintenance:**

```bash
python scripts/reverify_all.py     # recheck every claim, rewrite the registry, report and generated files
python tools/queue_builder.py      # rebuild the work queue from the binaries
```

## Repository layout

| Path | What it is |
| :--- | :--- |
| `reconstructed_src/*.cpp`, `*.h` | Hand-written translation units. Methods carry their address in a comment, e.g. `// PC VA 0x006E7EB0 (11 B)`. |
| `reconstructed_src/imported/` | Bulk files from earlier sweeps. They are rechecked like everything else; new work goes through the portal. |
| `reconstructed_src/Original_Binary_Order_*.cpp`, `pc/`, `xbox/` | **Generated** from the registry: every verified function in address order, and grouped by subsystem and class. |
| `reconstructed_src/Partial_Proven_Checkpoints.cpp` | Best partial attempts saved by the portal. Not verified. |
| `include/` | Shared headers. |
| `reports/verified_registry.json` | The record of what is verified, with the code, flags and who verified it. |
| `reports/reverify_report.md` | Every claimed function, its status and the reason. |
| `tools/` | Verifier (`msvc_verify.py`), binary reader, queue builder, C++ policy, decomp.me export (`decompme.py`), look-alike grouping (`lookalikes.py`), script-format tools (`torque_dso.py`, `rcf.py`). |
| `START_PORTAL.bat`, `start_portal.sh` | Double-click (Windows) or `sh` (macOS, Linux) launchers for the portal. |
| `scripts/extract_scripts.py`, `tools/rcf.py` | Copy the game's script files out of your own `cement.rcf` (see `docs/SCRIPTS.md`). |
| `scripts/` | Compiler setup, re-verification, maintenance. |
| `website_kit/index.html` | The portal's web page. |
| `docs/index.html` | The public project website: live progress and every verified function (see `docs/README.md`). |
| `docs/METHODOLOGY.md` | Verification rules and code generation notes. |
| `docs/GAME_VERSIONS.md` | Which copies of the game are accepted (US versions only), with their SHA-256, and what may be shared. |
| `docs/OTHER_VERSIONS.md` | The PS2 and Wii versions: what is known, and what a decomp of them would need. |
| `SCARFACE_DECOMP_AI_HANDOFF.md`, `AGENTS.md` | Brief for AI assistants (served by the portal at `/download/ai-handoff`), and how an agent uses the portal API. |
| `tests/` | Test suite (`python -m pytest -q tests/`). |
